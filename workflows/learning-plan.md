# Learning Plan Workflow

For each priority domain, classify concepts as:
- Required: needed for EXPECTED depth.
- Repair: prerequisite gaps blocking progress.
- Practice: known concept needing interview fluency.
- Stretch: beyond expected depth.

Sequence by prerequisites, not popularity. Each study block should include:
1. learn mechanism
2. reason about failure
3. solve a scenario
4. explain trade-offs aloud
5. short interview drill

Every preparation plan must use a three-level topic hierarchy. Each week or phase must name its primary domain or topic, each topic must list its subtopics, and each subtopic must list concrete sub-subtopics. Do not provide a flat list of technologies.

Use this structure:

```text
Week 1: Database transactions
  Topic: Transaction fundamentals
    Subtopic: Atomicity
      Sub-subtopics: commit, rollback, partial failure
    Subtopic: Isolation
      Sub-subtopics: dirty reads, lost updates, write skew
```

For every topic, subtopic, and sub-subtopic, state the expected outcome or explain why it is included. Add a checkpoint at the end of each week or phase. Keep required, repair, practice, and stretch labels visible at the appropriate level.

Reassess after each major block and update CURRENT/TARGET.

Do not start a learning block until the initial diagnostic completion gate has produced the depth analysis and timeline. Begin with the first repair or required topic selected from that analysis, then adapt the sequence when later answers provide new evidence.
