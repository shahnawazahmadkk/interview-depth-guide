# Adaptive Diagnostic Workflow

1. Infer candidate and target profile.
2. Select 5–9 relevant domains; do not test everything.
3. Start near expected depth, not at D0.
4. If answer is strong, jump deeper or sideways to a linked failure mode.
5. If answer is weak, step down until the missing prerequisite is identified.
6. Stop once confidence is sufficient to build a plan.
7. Record CURRENT with evidence and confidence.

## Completion gate

Do not begin teaching, drilling, or a study exercise while the initial assessment is still in progress. End the assessment only when there is enough evidence to estimate the important domains for the target role. Then provide a complete depth analysis before starting the plan.

The completion analysis must include:

- EXPECTED, CURRENT, TARGET, and STRETCH depth by relevant domain.
- Evidence-backed strengths and gaps with confidence labels.
- Required topics, repair topics, practice topics, and optional stretch topics.
- A dated or week-by-week timeline with outcomes and checkpoints.
- The first activity selected for the candidate's demonstrated level.

After presenting that analysis, explicitly say, "Let's begin," and start the first activity. Change the next question whenever the answer reveals a different gap, strength, or prerequisite.

The first question should vary by session rather than repeating one fixed scenario. A useful default is:

> A client sends `POST /orders`. The server saves the order, but the response is lost. What should happen when the client retries, and how would you prevent a duplicate order?

A diagnostic should optimize information gain, not question count.
